# 完整 App 化方案（窗口 App + 内嵌服务 + TOML 凭证配置）

## 目标形态

一个真正的 macOS App：`~/Applications/Model Router.app`，Dock 图标 + 主窗口，**Go 服务二进制内嵌在 App bundle 里作为子进程运行**。打开 App → 服务起；退出 App（Cmd+Q / 菜单 / Dock 退出）→ 服务同步退出；红叉关窗 → App 留在 Dock、服务继续跑（你已确认）。launchd 彻底移除，开机自启用「登录时启动」开关（SMAppService）代替。API 凭证放进 `~/.codex-router/config.toml`（Claude Code 风格），UI 和 CLI 都写这个文件。

```
Model Router.app/Contents/
├── MacOS/ModelRouterTray      ← Swift 主程序（窗口 + 菜单栏）
├── MacOS/codex-router         ← Go 服务二进制（子进程，注册表 go:embed 内嵌）
└── Resources/（AppIcon.icns 已存在）

~/.codex-router/config.toml     ← 凭证配置（0600）
[zai-coding]
api_key = "sk-..."
[opencode-go]
api_key = "..."
```

## Phase 1 — Go：自包含二进制 + TOML 凭证

1. **注册表 go:embed**：`git mv config internal/registry/config`（go:embed 不允许 `..` 路径），`registry.Load` 优先用 `--config` 显式目录（开发），否则用内嵌 FS。二进制从此不需要旁边的 config/ 目录——install 的 `copyConfigTree`/`writeControlLauncher` 删除。
2. **TOML 配置文件**：新包 `internal/tomlconf`——极简 fail-closed 解析器（`[table]` + `key = "string"`，转义、注释、拒绝 dotted key/多行串；参考 `src/toml-structure.mjs` 的思路），只服务我们自己写的文件。
3. **凭证解析顺序变更**（`internal/cred/cred.go`）：`environment → config.toml → *.secret 文件 → keychain`，新增来源标签 `"config"`（tray 的 credentialSource 自动显示）。逐请求解析、改文件即时生效（与 .secret 行为一致）。
4. **`control credential` 重写**：改为原子写/删 config.toml 的 `[provider] api_key`（0600）。stdin 提示流程保留（终端用户）。tray 的 Add Key 走同一命令，自动落到 TOML。
5. **config 模板**：`control config init`——文件不存在时生成带注释的模板，方便发现；设置页「打开配置文件」按钮用它。
6. **服务生命周期适配**：`serve` 启动时写 pidfile 到状态目录；`control service stop` 改为读 pidfile → SIGTERM（不再依赖 launchd bootout）；`control service start` 分离进程直接 spawn serve（终端救急用）。
7. **install/uninstall**：install 删掉 launchd 注册（保留 secrets/启用列表/catalog/config.toml 块）；uninstall 保留 launchd 清理代码但只用于清除旧安装遗留的 plist。

## Phase 2 — Swift：窗口 App + 子进程托管

1. **双场景**：`WindowGroup`（主窗口，复用现有 TrayView 内容，初始 ~420×640、可缩放、窗口头部加 App 图标）+ 保留 `MenuBarExtra`（状态速览）。`Info.plist` 的 `LSUIElement` 删除、激活策略改 `.regular`——Dock 出现图标。
2. **runControl 改造**：优先用 bundle 内 `Contents/MacOS/codex-router`，回退链 `ModelRouterSourceRoot/bin/control`（开发）→ `~/bin/codex-router`。不再硬性要求 `<root>/bin/control` 存在。
3. **ServiceSupervisor（新类）**：App 启动 → 探活 `/health`，没跑才 spawn 子进程 `serve --state ~/.codex-router`；`terminationHandler` 监控子进程，意外退出且端口不健康时退避重拉（bind 冲突=外部已有实例，不重拉）；`applicationWillTerminate` → SIGTERM 子进程并等待退出。替换现有 `ensureServiceRunningAtLaunch`/`stopServiceOnQuit` 的 launchctl 路径。
4. **设置页新增**：「登录时启动」开关（SMAppService.mainApp register/unregister + 状态显示）；「打开配置文件」按钮（不存在先 `control config init`，再 NSWorkspace 打开）；provider 卡显示凭证来源（config/file/env）。
5. 红叉关窗 = 默认 SwiftUI 行为（窗口关、App 留 Dock、服务不停）——不需要额外代码，验证即可。

## Phase 3 — 构建脚本 + 迁移

1. `scripts/build-macos-tray-app.sh`：swift build 后加一步 `go build -o <bundle>/Contents/MacOS/codex-router ./cmd/codex-router`，codesign 仍然最后（覆盖两个可执行文件）。`MODEL_ROUTER_TRAY_ROOT` 仅作开发回退。
2. 清理旧 launchd：`launchctl bootout gui/$(id -u)/io.github.codex-router.go` + 删除 plist。
3. 构建新 .app 替换 `~/Applications/Model Router.app`，open 验证。
4. `~/bin/codex-router` CLI 同步更新——**命令列出由你执行**（不主动 deploy）。

## Phase 4 — 端到端验证

- open App → /health OK → `codex exec` 真实流量通过（native + 路由）
- Cmd+Q → 服务进程退出；重开 App → 自动拉回
- 红叉 → 服务仍在（Dock 图标在）
- config.toml 填 key → picker 路由模型可用（需要你的真实 key，或验证 401 语义正确）
- `go test ./...` 全绿 + 新增 TOML/cred 顺序/pidfile 测试；`doctor` 各项 OK

## 边界与风险

- `git mv config` 保留历史；embed 后注册表变更 = 重编二进制（本来就是 commit 驱动，无损失）
- TrayView 是为 352px 弹出窗调的字体/布局，窗口化先复用后续打磨，本期内做适度放大
- 旧 launchd plist 若不清干净会出现双服务抢端口——迁移步骤显式处理
- 终端 `~/bin/codex-router` 与 bundle 内二进制并存：端口唯一，后启动者 bind 失败退出，Supervisor 探活避免双拉
